Design & Decisions
Key design choices
  • Stage 1c is incremental PRs into main (not optimize-inference-time; that landed in #5).
  • P0 is inventory only. P1a is wall-clock only. No Euler/decode/quant change until G1 is green.
  • Timers are opt-in (ALPAMAYO_STAGE_TIMERS=1) so the default e2e path stays unchanged.
  • Encode is timed around vision_tower only.
  • Prefill is the first token: language_model(...) on the prompt (seq_len > 1) plus mx.eval(logits) inside AlpamayoModel.__call__. After token 1, one-token LM calls are decode (warm KV).
  • T1.1 is greedy e2e + ALPAMAYO_STAGE_TIMERS=1.
  • P2a: one mx.eval after the Euler loop. Mid-loop clear_cache removed so it cannot sync every 3 steps.
Why

The speedup plan forbids Phase 3 quant until G1 fields exist. A clock that dumps encode into prefill would pick the wrong first cut.

Rejected
  • Always-on timers / extra eval on the default path — would change sync vs 1b e2e.
  • 4-bit expert or vision first — plan forbids it before G1.
  • Merging P1a without a documented .venv table — already happened; do not repeat.
