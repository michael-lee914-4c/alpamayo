Alpamayo 1 on MLX:
make inference fast enough to train

This is Stage 1c of alpamayo_mlx_port_plan.html. Target machine: Mac M4 Max, 128 GB unified memory. Current single-window inference is ~110 s. That is ~150× slower than the NVIDIA baseline for the same 10B VLA (~704 ms) and blocks any practical SFT or RL loop. Quantization is one lever, not the first one. Stage 1b (action expert / physical pred_xyz) is closed — leftover yield/stop quality is on reports/stage1b_progress.html. Progress report: reports/stage1c_progress.html. Stages 2–3 stay blocked until Bar B is green.

1. Mission and success bars

Produce a faster Alpamayo 1 MLX inference path so on-device training is possible. Prefer changes that keep trajectory quality (minADE / ADE@6.4s) and CoT validity. The 10B model is the teacher. A smaller student is an allowed end-state if the teacher cannot be rolled out cheaply.

Bar A — Diagnose

Stage timer for one window: encode / prefill / CoT decode / flow-matching. Dtype, compile status, num_traj_samples, FM steps, max CoT tokens recorded.

Bar B — Trainable

Teacher-forced or CoT-disabled train step on M4 Max in tens of seconds or less, not 110 s. LoRA/QLoRA path works.

Bar C — Fast infer

Single-window inference toward a few seconds, then <2 s if streaming + speculative CoT land. Quality within ~0.1–0.2 m ADE of the bf16 port on a fixed 50-clip slice.

Four-stage inference (this is the unit of work)

  1. Encode — vision tower over 16 frames.
  2. Prefill — backbone over vision + ego + prompt tokens (compute-bound, long sequence).
  3. Decode — autoregressive Chain-of-Causation text (memory-bound per token).
  4. Action — 10× (or N×) 2.3B expert forwards, KV from the VLM reused across steps.

FlashDrive stage split on 1.5 / RTX PRO 6000: encode 88 · prefill 177 · decode 264 · action 187 = 716 ms. No single stage is the whole bill. Do not optimize blind.

MLX constraints — still true as of late Aug 2026

  • nn.quantize(..., mode="affine", bits=4, group_size=64) is the production weight-only path. Bits in {2,3,4,5,6,8}. Predicate may return a dict of {bits, group_size}.
  • QuantizedLinear packed integer weights are frozen. No gradients through the int codes. DWQ unfreezes only scales and biases.
  • Activation quant (QQLinear, quantize_input=True) only for nvfp4 / mxfp8.
  • Train paths that exist: QLoRA on a frozen quantized base; DWQ distillation of scales/biases; LoRA on bf16; community fake-quant QAT in mlx-lm-lora. There is no “full finetune the 4-bit 10B.”
  • mx.compile is the CUDA-graph analog. Official NVIDIA code has enable_diffusion_expert_cuda_graph() — that API is CUDA. Reimplement with compiled fixed-shape MLX closures.

3. Do not do

STOPHard constraints
  • Do not quantize the whole model to uniform 4-bit as the first change.
  • Do not 4-bit the action expert or vision tower until the language tower is proven.
  • Do not start a multi-day QLoRA run before Phase 1 timers exist.
  • Do not try to backprop through packed QuantizedLinear.weight.
  • Do not set num_traj_samples>1 or max_generation_length=256 inside a training loop.
  • Do not evaluate quality with a single cherry-picked clip. Use a frozen 50-clip slice and the same seeds.
  • Do not claim “FlashDrive on Mac.” Reimplement the techniques.
  • Do not switch to Alpamayo 1.5 mid-stream unless the user says so. This plan is Alpamayo 1 / R1-10B.

Phase 0 — Inventory the port

Owner: Port agent. Depends on: access to the user’s MLX tree. Timebox: 2–4 hours.

T0.1Map modules to the four stages→ T1.1

Walk the MLX port and write a one-page map:

  • Vision encoder class, input shape after processor, token count per window.
  • Backbone class (Cosmos-Reason / Qwen3-VL lineage), layer count, dtype.
  • Generation loop: KV cache? mx.eval per token? compiled?
  • Action expert class, how KV is passed in, FM num_inference_steps.
  • Current num_traj_samples, max_generation_length, temperature / top_p.

Done when: a short PORT.md exists with file paths and those numbers filled from code, not memory. Landed: mlx_port/PORT.md (2026-08-29).

If any hot path is float32, that is a Phase 2 bug, not a Phase 3 job. Search for mx.eval inside token and FM loops — per-step eval will dominate 110 s by itself.

Done when: dtype of backbone, vision, expert, and action projections is written down. Count of mx.eval / .item() / numpy roundtrips in one window is written down.

Phase 2 — Compile, dtype, cut train-time work

Owner: Perf + train agents. Depends on: G1. Expected impact: often 3–10× on a naive first port, before any quant. Timebox: 1–2 days.

T2.1bf16 everywhere that is still fp32

Backbone, expert, projections, vision. Leave LayerNorm/RMSNorm as the port already does. Done when: no fp32 matmul remains on the hot path; T1.1 rerun.

T2.2Compile fixed-shape closures
@mx.compile
def diffusion_step(x, t, *kv):
    return expert(x, t, kv)

@mx.compile
def backbone_block(h, mask, cache):
    return block(h, mask, cache)

Capture once. Recapture if batch, cameras, or token length change. Do not compile a Python generation loop that changes shape every token unless you have a decode-step closure with static cache views.

Done when: FM step and at least one backbone block are compiled; T1.1 shows lower launch overhead or lower ms/step.

T2.3Kill per-step eval and host roundtrips

One mx.eval at the end of encode, at the end of prefill, after CoT (or per decoded chunk), after the FM loop — not inside the Euler integrator and not after every token unless you are streaming text to a UI.

Phase 3 — Mixed-precision PTQ

Owner: Quant agent. Depends on: G2. Timebox: 1 day for affine mix, +1 day if ParoQuant loads.

T3.1Recipe A — mixed affine (must ship first)
import mlx.nn as nn

KEEP_DENSE = ("vision", "visual", "vit", "action", "expert",
              "lm_head", "embed", "embed_tokens")

def pred(path, m):
    if not hasattr(m, "to_quantized"):
        return False
    pl = path.lower()
    if any(s in pl for s in KEEP_DENSE):
        return {"bits": 8, "group_size": 64}   # or False for bf16
    return {"bits": 4, "group_size": 64}

nn.quantize(model, group_size=64, bits=4, mode="affine", class_predicate=pred)

Adjust path substrings to the real module names from T0.1. Default group size 64. Do not start at group 32 unless quality fails — gs32 is slower on Metal because of scale traffic.

Done when: checkpoint saved; T1.1 rerun; 50-clip ADE and a CoT exact-match or token-level agreement vs bf16 recorded.

T3.2Recipe B — ParoQuant language tower

Preferred 4-bit for CoT. Naive affine 4-bit is known to drift on multi-token reasoning traces.

  1. pip install "paroquant[mlx]"
  2. Attempt to load z-lab/Alpamayo-R1-10B-PARO language weights into the MLX backbone. Expert stays Recipe A or bf16.
  3. If the companion does not map 1:1 onto the port’s parameter names, run ParoQuant conversion on the port’s own backbone weights.

Done when: either PARO loads and beats Recipe A on CoT agreement, or a written reason it cannot (name mismatch, missing kernel, license) is in the handoff.

T3.3Quality slice

Freeze 50 PhysicalAI-AV clips. Report minADE@6.4s, ADE@6.4s, off-road if you have it, and whether CoT still contains the expected causal structure (not just perplexity). Fail Recipe A if ADE regresses >0.2 m or CoT becomes garbage. Then bump last N layers + head to 6/8-bit, or run T4.2 DWQ.

G3Gate

Quantized infer is faster than G2 on decode and/or prefill. ADE within 0.2 m of the Phase 2 bf16 port. Action expert still not 4-bit unless T3.3 explicitly says it survived.

Phase 4 — Train in low precision the MLX way

Owner: Train agent. Depends on: G3 (or G2 if staying bf16 LoRA). Timebox: 2–4 days including a short SFT smoke.

NVIDIA’s own SFT is two stages on 8×H100: Stage 1 backbone (CoC can be off), Stage 2 expert. Reproduce that split on one Mac, at much smaller batch.

T4.1QLoRA backbone, denser expert
  • Freeze W4/PARO language weights.
  • Inject LoRA on q, k, v, o, gate, up, down of the backbone. Rank 8–16 to start.
  • Leave the 2.3B expert in bf16 or W8. LoRA it in Stage 2, or train it dense — 128 GB can hold that.
  • Do not update packed ints.

Done when: one Stage-1 smoke (e.g. 50–100 steps, batch 1) completes without OOM; loss trends down; peak memory logged.

T4.2DWQ if Recipe A CoT is weak

Use the MLX DWQ path: freeze packed weights, train scales/biases with KL to a bf16 or W8 teacher on driving CoT + hidden states. Calibrate on AV clips, not WikiText. DWQ pays off at 2–4 bits; skip it at 8-bit.

Done when: student-teacher KL dropped and T3.3 CoT metric improved, or DWQ is marked skip with a reason.

T4.3Train step that does not generate

For SFT, teacher-force CoT tokens and run a single FM training forward (the flow-matching train loss already samples a timestep — it does not need 10 Euler steps). The 110 s number is an inference window. A correct train step should be encode + one backbone forward + one expert forward, not a full rollout.

If the current “training” code calls sample_trajectories_from_data_with_vlm_rollout every step, that is the bug. Replace it with the official SFT graphs (stage1 VLM CE / stage2 CFM loss).

Done when: train-step timer does not include autoregressive CoT or a 10-step Euler loop unless the run is RL rollout.

G4Gate

SFT smoke works. Train step time is in a different regime from 110 s infer. Checkpoint can be fused (LoRA→dense) or served as base+adapter.

Phase 5 — Pipeline: stream, speculate, skip FM steps

Owner: Systems agent. Depends on: G3. Do in parallel with Phase 4 if people allow. This is how you leave the multi-second infer regime.

T5.1Streaming vision KV

Windows overlap ~75%. Encode only new frames. Keep a persistent KV. Evict the oldest vision span. FlashDrive: encode 88→12.5 ms on NVIDIA after this. On MLX, even a coarse “reuse last 12 of 16 frame embeddings” is a win for closed-loop training.

If streaming hurts ADE, finetune only the action expert (FlashDrive result: full-VLM stream-FT made ADE worse; expert-only recovered).

T5.2Speculative CoT

Domain CoT is short and low-entropy (~16 tokens). Worth doing only if T1.1 says decode is a large slice.

  • Draft weights: z-lab/Alpamayo-R1-10B-DFlash (2-layer, block size 8).
  • Runtime reference: dflash-mlx (community MLX speculative loop). FlashDrive itself will not run.
  • Acceptance must be exact (verify with the target). Do not ship approximate drafts into a planner.
T5.3Adaptive flow matching

FlashDrive caches mid-schedule velocities when relative change is small (they cited cosine >0.99). Implement a cheap version: run steps {0,1,2,N-2,N-1,N} live, reuse mid. Compare ADE to full 10-step on the 50-clip slice. Keep the setting that wins.

G5Gate

Infer window is a few seconds or better. ADE still inside the 0.2 m band. Document which of T5.1–T5.3 actually moved the needle on M4 Max — do not keep dead code.

Phase 6 — Distill a student

Owner: Distill agent. Trigger: after G4, teacher rollout is still too slow for RL. This is NVIDIA’s intended product path.

T6.1Teacher dump

Run the best teacher (Phase 3/5) offline over the train split. Store CoT text + future xyz/rot. No need for this to be real-time.

T6.2Student

1–3B VLM + small FM head, 4-bit MLX, LoRA. Train on the dump. The policy you RL is the student. Keep the 10B as labeler / critic.

Done when: student train step is comfortable on M4 Max and closed-loop or ADE is measured against the teacher, not against hope.
